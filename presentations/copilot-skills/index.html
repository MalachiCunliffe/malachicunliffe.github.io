Make good work repeatable.

Turning a successful way of working into a process you can use again—with less repeated prompting and more consistent execution.

We’re talking about GitHub Copilot, the engineering assistant—not Microsoft 365 Copilot.

The problem with “just do it”

What makes a cheeseburger repeatable?

  • Ask everyone to “make a burger” and you’ll get different results.
  • McDonald’s provides ingredients, assembly instructions, and quality checks.
  • A shared process helps different people produce a consistent result.

Same recipe. Reliable result.

A useful mental model

The agent is the cook.
The skill is the recipe.

Agent

Carries out the work.

Skill

Provides a reusable process for a specific task.

Instructions + resources

Explain what to check, which sources to use, and when to stop.

The process stays consistent; findings depend on the task.

The reusable recipe

What the skill does.

  • Identifies the current version and the target under our N−1 policy.
  • Reviews official release notes and upgrade guidance.
  • Identifies breaking changes, affected code, and required actions.
  • Produces an evidence-backed recommendation.
  • Separates assessment from implementation, with clear stopping points.

Live demo · Watch the process

Three things to look for.

01 / PROCESSDoes it follow the checks?

Watch the skill guide the upgrade assessment.

02 / EVIDENCECan you verify the findings?

Look for explanations grounded in cited sources.

03 / BOUNDARIESDoes it know when to stop?

It should not take unauthorised action.

Review the recommendation, then decide the next step.

Build skills agents can reuse

“When you find a way of working that works, capture the recipe.”

  • Capture repeatable processes as shared skills.
  • Improve the process once and share those improvements.
  • Give agents the skills they need for their work.
  • Start with one task you keep explaining.
